CSS Modules

Having something like:

        const styles = {
          ...sidebarStyles,
          ...subheaderStyles,
          ...filterStyles,
          ...tableStyles,
          ...paginationStyles,
          ...pipelineListStyles,
        };

isn't slow. Next.js doesn't just scan these different CSS style files at runtime, it's resolved at buildtime. When Next.js processes a module.css file, it gives you a plain JS object of name mappings like (for sidebarStyles):

          {
            "sidebar": "sidebar_sidebar__a3Kx9",
            "sidebar-content": "sidebar_sidebar-content__b7Rp2",
            "profile": "sidebar_profile__c1Lm4",
            // ...
          }

These are hashed names, meaning it's an O(1) object key lookup on this pre-built dictionary. So by the time a component runs, "styles" is already a fully resolved JS object sitting in memory.


REGEX to convert classes to 'className' in .tsx files:

      REPLACE something like 'class="page-content"' to 'className={styles.page-content}:

            Find:
            class="([^"]+)"

            Replace:
            className={styles.$1}


      REPLACE something like 'className={styles.page-content}' to 'className={styles['page-content']}'

            Find:
            className=\{styles\.([a-zA-Z0-9_-]*-[a-zA-Z0-9_-]*)\}

            Replace:
            className={styles['$1']}


      REPLACE something like 'className={styles.pill pill--queued}' to 'className={`${styles.pill} ${styles['pill--queued']}`}'

            Find: className=\{styles\.([a-zA-Z0-9_-]+) ([a-zA-Z0-9_-]+)\}

            Replace: className={`${styles.$1} ${styles['$2']}`}

Adding this media query to globals.css has no effect because of load order. globals.css loads first, page CSS modules load after. So we move this into sidebar.module.css and use :global(), and since the sidebar component's CSS loads after globals.css, it wins the cascade fight

          @media (max-width: 874px) {
            :global(.page-content) {
              margin-left: 0;
              padding: 60px var(--space-xl) 0;
            }
          }

Bug Fix:.page-content override 

app/pipelines/new (CSS):

      :global(.page-content) {
        margin-top: var(--size-topbar-height);
        padding: 0;
      }

the :global(.page-content) rule gets injected into the browser when you're on pipelines/new/page.tsx. When you click a link from the pipelines/new/page.tsx page back to app/pipelines, it will inherit the editor's padding: 0 override and mess up the .page-content styling of the page UNLESS you specifically type in "/pipelines" in the URL. 

This happens because you use ":global()" for the .page-content

The fix is to scope it like this:

      .editor-main {
        margin-top: var(--size-topbar-height);
        padding: 0;
      }

So that it the changes to .page-content (now .editor-main) apply only to app/pipelines/new/page.tsx and NOT app/pipelines/page.tsx when you click a link back.
